# Designer research sessions — plan (DIY-first slide skill)

**Last updated:** 2026-10-05  

**Purpose:** Run 45-minute designer sessions to extend an existing Cursor skill (PowerPoint / slide design and computation) with clear DIY paths, “good enough” thresholds, optional expert escalation, and recognition of non-slide formats.

---

## 1. North star

| Priority | Intent |
|----------|--------|
| **DIY (primary)** | Most situations resolve with **tool recommendations + self-serve guidance** (including the slide skill). |
| **Good enough** | Define the **minimum viable output** that unblocks the stakeholder—not the best possible deck. |
| **Expert (secondary)** | Expert support is **easy to find and scoped by topic**; not the default path. |
| **Formats** | Detect when **slides are not the right deliverable** (one-pager, agenda, facilitator guide, etc.). |

**Phone / Coms Pro (high level):** Mobile is for capture, context, approve—not the main place to build decks. Heavy design and compute stay in **Cursor** with the skill.

---

## 2. Sample bias (acknowledge in every synthesis)

Designers in this panel are typically reached **only in high-stakes situations**. That is useful for:

- Escalation triggers and “when expert help was worth it”
- Edge cases and **other formats**
- Calibrating **good enough vs perfect** under pressure

It is **not** representative of:

- Everyday DIY behavior or baseline tool literacy
- How often people would self-serve if you never showed up

**Synthesis rule:** Label findings as **HS-supported**, **DIY-supported**, or **HS-only hypothesis**.

---

## 3. Session design

### 3.1 Duration and load

- **Length:** 45 minutes  
- **Priming:** ~8 min — objective + **output family** (two tiers: DIY minimum vs expert uplift)  
- **Inputs:** **4 per designer** (~8–9 min each)  
- **Close:** ~3 min — one line per input (dominant DIY path + good enough + escalate if any)

### 3.2 Order of content

1. **Objective** (one sentence)  
2. **Output family** (thin — artifact names + one-line examples, not full mocks)  
3. **Assigned inputs** (varied per designer)  
4. **Close capture**

**Priming is intentional:** Share output families up front so feedback is about fit, not reinventing deliverables.

### 3.3 Input pool

- **30 total:** **10 new** + **20 old** (historical / prior situations)  
- **Tag every input:**

| Tag | Use |
|-----|-----|
| **HS** | Real high-stakes (matches how you usually reach them) |
| **DIY** | Lower stakes, clear brief, good-enough is obvious (include synthetic if needed) |
| **Contrast** | Same theme as an HS input but stripped (shorter deadline, fewer stakeholders) |

**Per-designer mix (recommended):** **2 HS + 1 DIY + 1 contrast** (or **2 HS + 2 DIY** if contrast is folded into DIY).

Without DIY/contrast tags, results will over-recommend expert involvement.

### 3.4 “Negative” / contrast entry

- Use **incomplete block assignment** — not everyone sees the same four inputs.  
- Include **1 contrast or ambiguous input** per bundle where possible to test whether designers still land on the same **DIY output family**.  
- Counterbalance order and bundles (spreadsheet or Latin-style rotation).

---

## 4. Coverage math

**Designer-slots** = inputs × replications (R).  
**Scenarios per designer (K)** ≈ (inputs × R) / panel size (P).

At **4 inputs/person** in 45 minutes:

| Goal | Slots needed |
|------|----------------|
| 30 inputs × R=4 | 120 slots → ~30 designers in one round |
| 30 inputs × R=3 | 90 slots → ~22 designers |

**Prioritize the 10 new inputs at R = 4** (reporting bar). Old inputs can be R = 1–2 in round 1.

### 4.1 One round — 12 designers (48 slots)

| Allocation | Slots |
|------------|-------|
| 10 new × R=4 | 40 |
| 8 old × R=1 | 8 |
| **Total** | **48** |

- All **10 new** each seen by **4 designers**.  
- **8 old** seen once; **12 old** deferred to round 2.

### 4.2 One round — 16 designers (64 slots)

| Allocation | Slots |
|------------|-------|
| 10 new × R=4 | 40 |
| 12 old × R=2 | 24 |
| **Total** | **64** |

- **8 old** deferred to round 2.

### 4.3 Two rounds (12 designers, fuller old coverage)

- **Round 1:** 48 slots as in §4.1  
- **Round 2:** 48 slots — remaining **12 old @ R=2** (24 slots) + optional second pass on high-variance **new** + deep-dives

## 5. Reporting threshold

- **Per input:** Report a dominant pattern only if **≥4 of the designers** who saw that input describe a **substantially similar** DIY path and good-enough output. (With R=4 on new inputs, that is full agreement on that item.)  
- **Cross-cutting pattern:** Prefer **≥4 designers on different inputs** (include **DIY-tagged** inputs) before calling something a global product rule.  
- If **4 HS-only** designers agree on “always escalate,” treat as **bias confirmation**, not DIY policy—unless **DIY/contrast** inputs show the same.

## 6. Facilitator script

### 6.1 Priming (8 min)

Read or paraphrase:

> We’re optimizing for **self-serve**: tools and a Cursor slide skill so people can reach a **good-enough** result without expert help. Expert support exists and should be **fast to find**, but it’s the exception. Some situations need **non-slide** formats—we want to recognize those.  
>  
> **DIY minimum** examples: outline, slide skeleton, speaker notes stub, export checklist, “use tool X for Y.”  
> **Expert uplift** examples: narrative polish, high-stakes data story, brand-critical layout, multi-format package.

Show a **one-page output family** (two tiers). Do not show high-fidelity mocks.

### 6.2 Per input (~8–9 min)

For each assigned input ID:

1. Present the scenario (brief + any transcript/context).  
2. **DIY path:** “What would someone do alone, with tools, in bounded time?”  
3. **Good enough:** “What’s the smallest output that unblocks the stakeholder?”  
4. **Format:** “Slide deck only, or something else?”  
5. **Escalate (optional):** “Only if ______, expert on ______ topic.”  
6. **Debias on HS inputs:** “If we hadn’t reached out, what would good-enough have looked like DIY-only?”

Capture verbatim phrases where possible.

### 6.3 Close (3 min)

For each of their 4 inputs: one line — **DIY tools + outputs + escalate flag (Y/N)**.
